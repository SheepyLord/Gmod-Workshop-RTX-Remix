# vr_combined_review.py

Reduces Q-review client and NLVR_P review server records into mandatory fail-closed combined checks.
Verifies 21 simultaneous overlay roles, walking/sprinting hand error below 0.8 units (2 cm at 40 u/m),
world-velocity release, bounded native spring/melee responses, eye-side proxies, held blink/shift,
stale FOLLOW fallback, unchanged corpse setting, wrist Exit/borrowed menu survival and cached refresh.
Inputs are parsed records from the standard production driver, no files/settings are changed.
Returns checks/metrics/success for the combined receipt; missing observations fail. No CLI/exit code.

The latest WIP requires native mass readback, new teleport IDs, matching held entity IDs at every
teleport displacement, no intervening release and a shift above the former 480-unit/s proxy cap.
Client held-surface lag also needs actual samples. Historical receipts are preserved; rerunning
this stricter reducer does not retroactively accept or relabel an older run.


Wall acceptance additionally needs blocking-geometry and grab-refusal witnesses for every lifecycle case. CPU control requires restored live server modules and fresh physical hands; paused-walk acceptance requires sync remain within reach. No historical receipts are rewritten.


Verification regressions exercise locomotion versus intentional gestures, held body wall/constraint safety, deferred window refusal, moving two-hand mesh-query rate, pending overlay cancellation, expected logical capture roles and ULib/unknown/reentrant view ownership. Tests retain failures from the prior source, use stand-ins without SDK, and remain in the normal gate.

The reducer additionally requires successful, grip-driven public carry setup for hold, blink and shift. Empty held-client samples and a shift below 480 units/s remain failures; no failed combined-02 receipt is relabelled.
